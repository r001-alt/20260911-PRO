# 開發計畫管理目錄 (`doc/dev/`)

本目錄用於存放所有新功能或重大重構之開發計畫。

---

## 規約準則 (Guidelines)

1. **討論先行**：功能開發前必須先進行充分討論，確認需求痛點、受影響之組件與 API。
2. **命名規範**：檔案一律命名為 `plan_<功能名稱>.md`。
   - 範例：`plan_export_excel.md`、`plan_gantt_chart.md`、`plan_rfi_multi_attachments.md`
3. **持續參照**：開發期間需以該計畫為準則進行實作與檢核。
4. **開發完成後回寫**：功能驗證通過後，將異動內容與最新規格回寫至 `doc/spec/` 對應章節，並可於該計畫文件頂端標記狀態為 `[已完成 / COMPLETED]`。

---

## 開發計畫範本 (Plan Template)

```markdown
# [功能名稱] 開發計畫 (plan_<功能名稱>.md)

**建立日期**：YYYY-MM-DD  
**負責人/代理**：Agent / Developer  
**狀態**：[草案 / 審查通過 / 開發中 / 已完成]  
**關聯需求**：簡要描述使用者需求背景

---

## 1. 需求與目標概述
- **目標**：具體要達成哪些功能？
- **使用情境**：工程人員/監造顧問如何使用此功能？

## 2. 系統架構與影響評估
- **前端變更**：
  - 新增/修改組件：`src/components/...`
  - 路由與狀態更新：`src/App.tsx`
- **後端變更**：
  - API 端點新增/修改：`server.ts`
  - 資料模型欄位調整：`src/types.ts`
- **相依套件**：是否需要新增 npm 套件？

## 3. 詳細實作步驟
1. [ ] 步驟一：定義型別與 API 端點
2. [ ] 步驟二：實作後端商業邏輯與例外防護
3. [ ] 步驟三：實作前端 UI 組件與互動
4. [ ] 步驟四：前後端整合測試

## 4. 驗證清單
- [ ] TypeScript 型別檢查 (`npx tsc --noEmit`) 通過
- [ ] 前端建置打包 (`npm run build`) 通過
- [ ] 手動互動流程驗證正常
- [ ] 回寫規格至 `doc/spec/` 對應章節
```
