# 第 01 章：系統架構與環境規格

## 1.1 系統目標與邊界
本系統提供營建機電統包工程之專案管理、敏捷任務看板與工程疑義（RFI）追蹤。主要服務對象為專案經理（PM）、機電結構工程師、品保安衛工程師與業主顧問/監造單位。

---

## 1.2 軟體架構規格
1. **後端架構**：
   - Express.js 提供 HTTP 服務與 RESTful API（所有路由前綴為 `/api/v1`）。
   - 內建記憶體資料庫 (In-Memory Database)，以 JavaScript 物件陣列維護狀態，支援快速檢索與原型開發。
2. **前端架構**：
   - React 19 單頁應用 (SPA)。
   - 開發環境中，Express 伺服器掛載 Vite 中介軟體 (`vite.middlewares`)，實現前端代碼修改免重啟之即時熱重載 (HMR)。
   - 生產環境中，提供 `dist` 目錄靜態託管服務，所有未匹配路由回退至 `index.html`。

---

## 1.3 本機執行環境與設定規格
1. **環境變數 (.env)**：
   - `PORT`：伺服器監聽通訊埠，預設值 `3000`。
   - `HOST`：監聽介面，預設值 `0.0.0.0`。
   - `GEMINI_API_KEY`：Google Gemini 服務密鑰（可選；未設定時系統啟用智慧模擬評估模式）。
2. **行程生命週期管理**：
   - 伺服器啟動時，將目前行程識別碼 (PID) 寫入專案根目錄之 `.server.pid`。
   - 伺服器捕捉 `SIGINT` (Ctrl+C)、`SIGTERM` 與 `exit` 事件，自動刪除 `.server.pid` 暫存檔。
   - 捕捉 `EADDRINUSE` 錯誤並給予使用者操作提示。

---

## 1.4 啟動與關閉自動化腳本規格
1. **啟動腳本 (`start_server.bat` / `start_server.ps1`)**：
   - 檢查系統是否安裝 Node.js (>= v18)。
   - 檢查 `.env`，若無則自動產生預設檔。
   - 檢查 `node_modules`，若未安裝則自動執行 `npm install`。
   - 檢查通訊埠 3000，若已被舊行程佔用則自動先呼叫關閉腳本釋放。
   - 延遲 3 秒並呼叫系統預設瀏覽器連線至 `http://localhost:3000`。
   - 執行 `npm run dev` 啟動主服務。
2. **關閉腳本 (`stop_server.bat` / `stop_server.ps1`)**：
   - 讀取 `.server.pid`，透過 `Stop-Process -Id <PID> -Force` 終止主行程。
   - 透過 PowerShell `Get-NetTCPConnection` 搜尋通訊埠 3000 上的監聽行程並進行清理，確保 Port 3000 100% 釋放。
   - 清理 `.server.pid`。
